# Oyuur (раньше Elevate) — паспорт проекта

## Что это
Мобильное приложение: трекер привычек с игрой и друзьями. У каждой привычки (хорошей или плохой: не есть сладкое, не курить, тренироваться) своё дерево. Раз в день человек нажимает на дерево — серия дней растёт, дерево растёт, из деревьев складывается его лес. Друзья видят серии друг друга и соревнуются.

Цель — не поделка для олимпиады, а продукт, который можно запустить на весь мир и превратить в компанию.

## Владелец
Один человек, бюджета пока нет (позже — семья / инвесторы). Общаться по-русски, просто.

## Решения (что уже решено)
- Платформа: настоящее мобильное приложение. Сначала Android, потом iOS.
- Тестировать удобно с компьютера.
- Рынок: весь мир.
- Шансы: у каждого дерева свои, до 3. Пропуск дня при наличии шанса — серия замораживается, дерево в этот день не растёт. 1-го числа каждого месяца +1 шанс (максимум 3). Шансов нет — дерево увядает и умирает, но остаётся в лесу как память с рекордом дней; из его семени можно посадить одно новое (следующее поколение той же привычки).
- Лес принадлежит аккаунту (решено 29.10.2026, OYUUR-28): обычные деревья хранятся на сервере как есть, скрытые («стыдные») — зашифрованной копией, ключ только у человека (пароль + код восстановления). Без аккаунта — как раньше, только на телефоне. Заменяет прежнее «на сервер уходят только деревья „Друзья“».
- Время полива (решено 29.10.2026, OYUUR-32/33, `design/oyuur-33/спец.md`): у каждого дерева своё время, с которого его можно полить; «Бросаю» — с 18:00, «Делаю» — в любое время; в день посадки — сразу; смена времени действует с завтра; игровой день длится до 3:00 ночи.
- Лес в аккаунте — подробности в `design/oyuur-29/спец.md`: под замком всё «Только я»; пароль не уходит на сервер; копии базы раз в сутки, 14 дней, вне homelab — на компьютере владельца (без облака).
- Виджеты Android (решено 29.10.2026, OYUUR-38, `design/oyuur-37/спец.md`): 2×2, 4×2, 4×4, 4×1 и вид «Простой»; с виджета не поливать — только открыть дерево; скрытые деревья — под именем дерева; «Сгорит шанс» — с 22:00. На iPhone (веб) виджетов нет.
- Покупка шансов (до 5 в месяц) — только на этапе 6, и только как запас, не воскрешение.
- Поколения одной привычки — одно место в лесу (стопка). Стрелки на главном экране листают поколения, свайп/точки — привычки.
- «Закрепить результат» — навсегда: дерево уходит с главного экрана в лес таким, каким было; нажимать и отменять нельзя.
- Главная фишка: друзья видят твои серии. Обманывать стыдно перед знакомыми — это и защита от читерства.
- Привычки любые, не только вредные.
- Каждое дерево можно скрыть от друзей; «стыдные» закрыты по умолчанию.
- Этапы из `ПРОДУКТ.md` (раздел 9) согласованы. Первая версия бесплатная, без сервера, магазина и валюты.
- Название — **Oyuur** («лес» по-якутски), решено владельцем 28.10.2026. Домены oyuur.me / .app / .com свободны (покупает владелец). Пакет Android `me.oyuur.app`.
- Тестовая онлайн-версия (28.10.2026): свой сервер на homelab владельца — https://oyuur.ayaal.savvinov.me (API + веб-версия), APK для друзей-тестеров через облачную сборку Expo (EAS, проект `@ayuaya123/oyuur`). Без админских функций. Аккаунт необязателен: @ник + пароль + одноразовый код восстановления, без почты. На сервер уходят только деревья с пометкой «Друзья» (+ число скрытых).

## Важные ограничения (из исследований)
- Google Play не платит на российские счета → платная часть только через компанию за рубежом.
- 152-ФЗ: данные россиян нельзя записывать в базы за границей → сервер решать с юристом.
- Личный аккаунт Google Play: перед публикацией 12 тестеров 14 дней.
- Для общения между пользователями обязательны жалобы и блокировка.

## Код
- `app/` — приложение: Expo SDK 58, React Native, Expo Router, TypeScript.
- `server/` — сервер друзей: Node 24 без зависимостей (http, crypto, sqlite), тесты `npm test`. Выкладка: `bash server/deploy.sh` (сначала `cd app && npx expo export -p web` — веб-версия кладётся в `public/`). Для разработки — свой сервер: `DB_PATH=./dev.db PORT=8790 node src/main.js` и приложение с `EXPO_PUBLIC_SERVER=http://localhost:8790`; аккаунты на боевом сервере не создавать.
- `app/src/net/` — запросы к серверу и очередь без сети; `app/src/state/friends.tsx` — `useFriends()` (аккаунт, друзья, общие деревья).
- `app/src/game/` — правила игры (чистые функции + тесты): `tree.ts` — дерево, `plot.ts` — места на участке леса, `naming.ts` и `nameText.ts` — имя дерева, `economy.ts` — жёлуди и магазин, `quests.ts` — задания, `achievements.ts` — награды, `profile.ts`, `nick.ts`, `shared.ts` — общее дерево, `leaders.ts`. Любое изменение правил — сначала тест.
- `app/src/state/store.tsx` — данные и сохранение (AsyncStorage, без сервера).
- `app/src/app/` — экраны, `app/src/ui/` — рисунки деревьев и общие элементы, `app/src/i18n/` — тексты RU/EN (новые тексты — в файлах разделов: `home`, `shop`, `art`, `me`, `friends`, `account`, `together`, `leaders`; тест следит за повторами ключей).
- Перед «готово»: `npm test` и `npm run typecheck` в `app/`.
- GitHub (решено 03.11.2026): публичный github.com/savvinovay/oyuur (аккаунт сына владельца), без лицензии. Туда уходит не история, а снимок master одним коммитом: `bash tools/push-github.sh "что нового"` (автор — скрытая почта GitHub). Пушить только с «да» владельца. CI `.github/workflows/ci.yml`: тесты приложения и сервера с покрытием (Codecov, секрет `CODECOV_TOKEN`), веб-сборка, APK через `expo prebuild` + Gradle (только ARM, открытый тестовый ключ, проверка подписи). Dependabot — раз в неделю.
- Expo меняется быстро: сверяться с документацией своей версии (см. `app/AGENTS.md`).

## Команда агентов (`.claude/agents/`)
Владелец хочет продукт уровня большой компании; большие работы делает команда, архитектор (основная сессия) делит работу, пишет задания, собирает и перепроверяет.
- `designer` — спецификация и макет до кода (`design/<волна>/`).
- `artist` — картинки нейросетью (Codex), отбраковка, сжатые файлы в `app/assets/`.
- `builder` — кусок кода по спецификации, в своей копии (worktree), с тестами; несколько параллельно.
- `qa-tester` — прогон сценариев в браузере 375×812 через Playwright, снимки, поломки.
- `product-critic` — жёсткая оценка «выглядит ли дорого» по снимкам.
- `code-reviewer` — поиск ошибок в diff перед коммитом.
Порядок волны: дизайн → показ владельцу → разработчики параллельно → тестировщик + критик + проверка кода → исправления → показ → метка версии.

## Диспетчер задач (решено владельцем 28.10.2026, настроен 28.10.2026)
Очередь задач — трекер Huly (`huly.savvinov.me`, проект `OYUUR`); если Huly недоступен — `ЗАДАЧИ.md`.
- Колонки Huly: Backlog = «Идеи», Todo = «Можно делать», In Progress = «В работе», «На проверке», «Нужна помощь», Done = «Готово», Canceled = «Отменено».
- Этапы — вехи (Milestones) в Huly, видны на сайте: «Этап 1 — Готово для друзей» (iPhone-веб, пуши, аналитика, жалобы, иконка APK, выкладка друзьям), «Этап 2 — Тест с живыми людьми» (раздача, отзывы, аналитика → новые задачи), «Этап 3 — Публикация в Google Play» (юрист, домены, нагрузка), «Потом — iOS и платная часть». Диспетчер сначала берёт задачи текущего этапа; новые задачи сразу ставит в этап.
- Что проверить владельцу — `ПРОВЕРИТЬ.md` в корне: по каждой задаче «На проверке» пошагово (что нужно, куда нажать, как понять, что хорошо, что написать диспетчеру). Диспетчер обновляет его при каждом переводе в «На проверке» и убирает пункт после Done; ссылается на него в сводке.
- Перед каждой выкладкой на сервер (с «да» владельца) — копия базы сервера; после — проверка, что вход, друзья и старые сохранения работают. Изменения сервера только добавляют (новые столбцы, таблицы, адреса), старые APK должны продолжать работать.
- Одновременно — до 2 исполнителей, если их задачи не трогают одни файлы (например, две спецификации в разных папках `design/`).
- Метка «владелец» — задачи, которые может сделать только владелец (домены, юрист, компания, тестеры, раздать APK, проверка на телефоне). Диспетчер их никогда не берёт в работу, только напоминает в сводке.
- Исполнители работают на высоком уровне рассуждения (диспетчер ставит `high` сразу после запуска); сам диспетчер — на обычном.
- Исполнитель работает в своей ветке (worktree). Ветку в `master` диспетчер вливает только после того, как владелец перевёл задачу в Done.
- Раз в час диспетчер смотрит очередь. Есть задача в «Можно делать» — запускает под неё отдельную сессию-исполнителя (одна задача — одна сессия — один коммит) и ставит «В работе». Лимита задач в день нет.
- Исполнитель доводит до «На проверке» (тесты, проверка кода, коммит). «Готово» и метку версии ставит владелец.
- Новые задачи диспетчер только предлагает в колонку «Идеи»; в работу переводит владелец.
- Сами: код, тесты, коммиты. Только с «да» владельца: выкладка на сервер, сборка APK, метки версий, траты, сообщения людям.
- Пустая очередь — взять одну мелкую задачу-ошибку из Backlog (без метки «владелец») и предлагать идеи в Backlog с пометкой «предложение диспетчера».
- Большую задачу сначала режет на маленькие в Huly и показывает нарезку владельцу.
- Тесты дважды упали — задача в «Нужна помощь», сообщение владельцу.
- Раз в день (первая проверка после 9:00) — сводка: что сделано, что посмотреть, где застряло. Владелец может в любой момент спросить «что происходит» — диспетчер отвечает по Huly и своим сессиям.

## Версии
- Каждая готовая версия — метка git `vX.Y` с описанием (v0.1 — этап 1, v0.2 — итерация 2, v0.3 — закрепление навсегда, …, v0.6 — живой главный экран, v0.7 — интерфейс: плашка-меню, система дизайна, звуки, v0.8 — «Мой лес» картой-участком с перестановкой, v0.9 — имя дерева, v1.0 — тестовая онлайн-версия: магазин, задания, профиль, друзья, общее дерево, лидеры, сервер).
- Номер версии — semver x.y.z (с 03.11.2026, первая — `v1.2.0`): `expo.version` в `app/app.json`, такой же в `app/package.json` и `server/package.json` (CI сверяет). Метка `vX.Y.Z` на GitHub собирает GitHub Release с APK и веб-архивом; метку ставить только с «да» владельца. Перед выпуском поднять `android.versionCode`.
- Список: `git tag -n`. Посмотреть старую версию: `git checkout v0.2`, вернуться: `git checkout master`.
