# Ключ подписи APK

Android ставит новую версию приложения поверх старой (лес остаётся), только если обе подписаны одним ключом или новая несёт «справку о передаче» от старого ключа.

## Что где лежит

| Что | Где | Секрет? |
|---|---|---|
| Ключ Oyuur `oyuur-release.p12` и пароль `password.txt` | `C:\Users\1\Oyuur-keys\` на компьютере владельца | **Да.** Не в git, не в чат, не в Huly |
| То же для GitHub | секреты репозитория `OYUUR_KEYSTORE_BASE64`, `OYUUR_KEYSTORE_PASSWORD` | Да, снаружи не видны |
| Старый открытый ключ `test-debug.keystore` (пароль `android`, имя `androiddebugkey`) | здесь | Нет, он есть в каждом проекте React Native |
| Справка о передаче `lineage.bin` (старый ключ → ключ Oyuur) | здесь | Нет, в ней только открытые части ключей |

Отпечатки (открытые, для сверки): старый ключ SHA-1 `5e8f16062ea3cd2c4a0d547876baa6f38cabf625`, ключ Oyuur SHA-1 `2e8942192a8c1b49eed1cfc9a41a104c57d15679`, SHA-256 `ee619651e2a4a78fc6a1615daa34f43b81067fbc45607fd871b5f59f87e6207f`.

## Как подписывается

`app/tools/sign-apk.sh` (его зовут `app/tools/build-apk.sh` и сборка на GitHub) подписывает APK двумя ключами сразу:
- **Android 9 и новее** видят справку и переходят на ключ Oyuur. После этого подделку со старым ключом поверх уже не поставить (проверено на эмуляторе Android 11).
- **Android 7–8** справку не понимают, проверяют старый ключ и тоже ставят поверх. Защиты на них не прибавляется.

В справке старому ключу оставлено только нужное для обновления: данные приложения и его собственные права (без права на права Android отказывается ставить поверх: `INSTALL_FAILED_DUPLICATE_PERMISSION`). Откат на старый ключ, общий UID и «вход» старым ключом запрещены.

Скрипт сам проверяет, что в подписи обе ступени (старый ключ → ключ Oyuur); иначе останавливается.

## Запасная копия — сделать сразу

Если ключ пропадёт, обновлять приложение поверх станет нельзя: друзьям придётся удалить и поставить заново (лес вернётся при входе в аккаунт, а то, что было только на телефоне, пропадёт).

1. Скопировать всю папку `C:\Users\1\Oyuur-keys\` на флешку (лучше на две) и убрать флешку в надёжное место.
2. Открыть `password.txt` и переписать пароль на бумагу или в менеджер паролей. Бумагу хранить отдельно от флешки.
3. Раз в полгода проверить, что флешка читается.

## Секреты для GitHub (один раз)

Без них сборка на GitHub делает только проверочный APK `*-test-key.apk` (его не раздавать), а выпуск по метке останавливается.

1. В PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\Users\1\Oyuur-keys\oyuur-release.p12")) | Set-Clipboard` — ключ в буфере обмена.
2. github.com/savvinovay/oyuur → Settings → Secrets and variables → Actions → New repository secret: имя `OYUUR_KEYSTORE_BASE64`, значение — вставить (Ctrl+V).
3. Ещё один секрет: имя `OYUUR_KEYSTORE_PASSWORD`, значение — содержимое `password.txt`.
4. Очистить буфер обмена (скопировать любое слово).

## Нельзя

- Класть `oyuur-release.p12` или пароль в git, чат, Huly, облако, почту, мессенджеры.
- Раздавать друзьям APK, подписанные только старым ключом (`*-test-key.apk`) или собранные в облаке Expo: на обновлённые телефоны они не встанут.
- Менять `lineage.bin` или делать новый ключ «на всякий случай»: справка привязана к этому ключу.

## Google Play (потом)

При публикации загрузить в Play App Signing этот же ключ Oyuur — тогда версии из магазина встанут поверх тестовых на Android 9+. Google подписывает одним ключом, без справки, поэтому на Android 7–8 тестовая версия поверх не обновится (там действует старый ключ) — только переустановка.
