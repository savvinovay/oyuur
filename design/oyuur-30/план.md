### Отступления от нарезки Т8 (осознанные)
1. **Вход v2 (Т5) переезжает из 31-Б в 30** — так просит задача: пароль больше не уходит на сервер уже сейчас. Делается только «ключ входа» (`authKey`), поля шкатулок (`wrapP`, `wrapR`, `kid`) сервер **принимает необязательными** и хранит, если пришли. OYUUR-31 начнёт их присылать. Для аккаунта v2 без `key_id` OYUUR-31 добавит маршрут «положить шкатулки» (с проверкой `auth`).
2. Вывод ключа (`scrypt` + `hkdf`) — маленький `app/src/net/kdf.ts` на `@noble/hashes`; OYUUR-31 построит `crypto.ts` рядом и возьмёт `wrapKey` из того же вывода.
3. `N = 2^15` по спецификации; параметры хранятся у аккаунта и меняются при следующей смене пароля. Замер на слабом Android — не сделан (нужен телефон), записать в отчёт.
4. Сохранение уже версии 5 (OYUUR-34) — наш переезд **v5 → v6** (в спецификации написано v4 → v5).
5. Удаление всего леса в аккаунте («Стереть всё») — через «эпоху» леса (`epoch`), см. ниже: спецификация не описывает, как стирание доходит до других устройств.
6. Исполнителей три, а не два: сервер ‖ логика приложения ‖ экраны (на заглушке `useSync`). Файлы не пересекаются.

## Договорённость о формате (сервер ↔ приложение)

### Записи (`records`, Т1.1)
| key | body |
|---|---|
| `tree:<id>` | дерево целиком (`Tree` из `tree.ts`) + `stamps: {nickname?, skin?, visibility?}` (HLC-строки). Только `visibility === 'friends'`, иначе `400 bad_record`. Сервер **проверяет** типы (id, lineageId, plantedOn, checkins — даты, размеры) и **хранит как прислали** (лишние поля не выбрасывает: это данные самого человека, иначе при обратной загрузке пропадут поля). Чистит — только вид для друзей. |
| `plot` | `{ places: { [lineageId]: { dc, dr, at } } }` — только открытые привычки; `dc/dr` — от центра (целые, \|x\| ≤ 20), `at` — HLC |
| `progress` | `{ ledger: {key: amount}, shop: {owned, seenAffordable, meadow, meadowAt}, quests, claimed, announced, tombs: {lineageId: HLC} }` — сервер проверяет, что это объект ≤ 256 КБ |
| `vault` | только OYUUR-31: `{v:1, kid, seq, n, c}`, непрозрачно, ≤ 1 МБ. Приложение в 30 её не шлёт. |

HLC: `<ms 13 цифр>-<счётчик 4 цифры>-<deviceId>`, сравнение строкой. Старое без отметки = `''` (проигрывает всему).

### Синхронизация
- `GET /api/sync?since=<rev>` → `{ rev, epoch, records: [{key, rev, deleted, body, at}], more }` (`at` — время сервера записи, мс; `body` — разобранный JSON или `null`). До 500 записей / 2 МБ за раз, по возрастанию `rev`.
- `POST /api/sync` `{ epoch, records: [{key, base, deleted?, body?}] }` → `{ rev, epoch, saved: [{key, rev}], conflicts: [{key, rev, deleted, body, at}] }`. Запись принимается, только если её текущий `rev` (0 — нет) `=== base`. Всё в одной транзакции. `epoch` не совпал → `409 wiped` (`{epoch}` в ответе).
- `POST /api/sync/wipe` `{}` → стирает все записи аккаунта (настоящее удаление), `epoch += 1`, `rev += 1`, `public` → пусто. Ответ `{rev, epoch}`. Устройство, у которого `epoch` старый, видит это в `GET` и **сбрасывает свой лес** (с копией в `elevate/v1-backup`) — так «Стереть весь лес» доходит до всех устройств.
- Лимиты: тело POST ≤ 1.5 МБ; `tree:*` ≤ 128 КБ; `plot`, `progress` ≤ 256 КБ; живых `tree:*` ≤ 1000 (`413 too_many_trees`); `400 bad_record` с `{key}`.
- После записи `tree:*` / `plot` / `progress` сервер пересобирает `users.public`: деревья — живые `tree:*` (чистка как в `publicView`), места `c = dc + size/2`, `r = dr + size/2`, где `size` — наименьший чётный ≥ 4, в котором помещаются все открытые места, + 2 (кольцо); луг — `progress.shop.meadow`; `hidden: 0`.
- **Поздние поливы:** таблица `watering_seen(user_id, tree_id, day, at)`, `INSERT OR IGNORE` для каждого дня `checkins` при записи `tree:*`. Нигде не показывается.
- `PUT /api/forest` (старые APK): работает, пока у аккаунта нет записей `tree:*`/`plot`/`progress`; после — `409 upgrade_app`. `hidden` друзьям всегда `0` (решение 12.1).
- `PRAGMA secure_delete = ON`. Удаление аккаунта стирает `records`, `watering_seen`, `kdf…key_id`.

### Вход v2 (Т5, без шкатулок)
`kdf = {alg:'scrypt', N, r:8, p:1, salt}` (соль — base64url 16 байт; N — степень двойки 2^13…2^17). `auth`, `recAuth` — base64url 32 байта (43 знака). Сервер хранит `hashSecret(auth)` в `pass_salt/pass_hash` (и `recAuth` в `rec_*`) при `auth_v = 2`.

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /api/auth/params?nick=` | — | `{v, kdf, recKdf}`; ника нет → `v:2`, соль = HMAC(секрет сервера, ник) (постоянная); `v:1` → `kdf:null` |
| `POST /api/signup` | **v2:** `{nick, kdf, auth, recKdf, recAuth, name, avatar, color, wrapP?, wrapR?, kid?}`; **старый:** `{nick, password, …}` — как было | v2: `{token, user}` (кода в ответе нет — его сделал телефон); старый — как было |
| `POST /api/login` | v2 `{nick, auth}`; v1 `{nick, password}` | v2 → `{token, user, wrapP, kid}`; v1-аккаунт с паролем → как было + `legacy: true`; v2-аккаунт с паролем → `401 wrong_login` (не принимаем пароль открытым текстом) |
| `POST /api/auth/upgrade` (сессия) | `{password, kdf, auth, recKdf, recAuth}` | только при `auth_v=1`: проверить пароль по старому отпечатку, `UPDATE … WHERE auth_v=1`; уже v2 → `409 already_v2`; неверный → `401 wrong_password` |
| `POST /api/password` (сессия) | `{oldAuth, kdf, auth, wrapP?}` (v2) | смена; все **другие** сессии удаляются → `{ok}`. Аккаунт v1 → `409 legacy` (телефон сначала делает upgrade) |
| `POST /api/password/reset-device` (сессия) | `{kdf, auth, recKdf, recAuth, wrapP?, wrapR?, kid?, newDek?}` | «не помню пароль» на устройстве со входом; v1 или v2 → становится v2; другие сессии удаляются; лимит 3/сутки (`429`); `newDek` стирает `vault` |
| `POST /api/recovery-code` (сессия) | `{auth, recKdf, recAuth, wrapR?}` | новый код (только v2) |
| `POST /api/recover` | v2 `{nick, recAuth}` → `{ticket, kdf, wrapR, kid}`; v1-аккаунт `{nick, code}` → `{ticket, legacy:true}`; **старый APK** `{nick, code, password}` → как было (только для v1-аккаунта; v2 → `409 upgrade_app`) | ticket — 10 мин, одноразовый |
| `POST /api/recover/finish` | `{ticket, kdf, auth, recKdf, recAuth, wrapP?, wrapR?, kid?}` | аккаунт → v2, все сессии удаляются → `{token, user}` |
| `POST /api/me/delete` | v2 `{auth}`; v1 `{password}` (как было) | |

Как узнать версию для `recover`: телефон сначала `GET /api/auth/params?nick` → `v` и `recKdf`.
Лимиты попыток — как у нынешних `/api/login` и `/api/recover`. Сервер в ответах `/api/me`, `login`, `signup` отдаёт `user.authV`.

### Приложение: вывод ключа (`net/kdf.ts`)
`master = scrypt(NFKC(password), salt, {N, r:8, p:1, dkLen:32})`; `authKey = hkdf(sha256, master, salt, 'oyuur/auth/v1', 32)`; `wrapKey = hkdf(…, 'oyuur/wrap/v1', 32)` (вернуть, но в 30 не использовать). Код: `code.toLowerCase().replace(/[\s-]/g,'')`, 12 знаков из `abcdefghjkmnpqrstuvwxyz23456789`, случайность — `expo-crypto.getRandomBytes`. Тест: известный вектор scrypt (RFC 7914) и совпадение с `node:crypto.scryptSync` + `hkdfSync`.

### Хранилище телефона (Т6)
`elevate/v1` версии **6** (+ `stamps`, `wallet.ledger`, места с `at`, `tombs`), `elevate/v1-backup` (копия перед первым слиянием/переездом, 30 дней), `elevate/v1-local` (лес телефона после «Оставить только лес аккаунта», 30 дней), `oyuur/sync`, `oyuur/device`, `oyuur/bound`.

### Кошелёк
`Wallet = { ledger: Record<string, number> }`, ключи Т3.5 (`w:`, `st:`, `sh:`, `q:`, `qb:`, `a:`, `legacy:<deviceId>`, `m:<YYYY-MM>`). `balance`/`earned` считаются функциями. Чтобы экраны не ломались, `useStore().wallet` остаётся объектом с числами `wallet.acorns` (баланс) и `wallet.earned` (их читают `shop.tsx`, `profile.tsx`, `ui/acorns/*`, `ui/shop/ItemSheet.tsx`); журнал хранится внутри.
