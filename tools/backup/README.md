# Копии базы Oyuur на вашем компьютере

Сервер каждый день после 4:00 (по времени сервера) сам делает копию базы и хранит 14 последних.
Эти скрипты раз в день забирают последнюю копию к вам на компьютер — на случай, если сервер или его диск умрут.

- Копия приходит **зашифрованной** вашим ключом владельца (тем же, что для страницы `/owner`). Без ключа файл бесполезен.
- Ключ хранится на компьютере зашифрованным средствами Windows: открыть его может только ваш пользователь Windows. В git его нет.
- Копии лежат в `%USERPROFILE%\Oyuur-backups` (например `C:\Users\1\Oyuur-backups`), 14 последних, файлы `oyuur-ГГГГ-ММ-ДД.oyuurbak`. Там же журнал `backup.log`.
- Нужен Node.js 24 или новее (уже стоит, если вы запускаете проект).

## Установка — 3 шага

Откройте PowerShell в папке `tools\backup` этого проекта.

**1. Запомнить ключ.** Скрипт спросит ключ — вставьте его (буквы не видны, так и должно быть):

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

**2. Проверить.** Скачать копию прямо сейчас:

```powershell
powershell -ExecutionPolicy Bypass -File .\backup.ps1
```

Хорошо, если в конце строчка вроде «Скачана копия за 2026-10-30 (2,3 МБ в зашифрованном виде). Проверка: ок, аккаунтов 12.»
Если пишет «ОШИБКА» — пришлите эту строчку диспетчеру.

**3. Включить каждый день.** Поставить задачу в Планировщик заданий Windows (каждый день в 14:00 и при входе в систему; если компьютер был выключен — сделает, как только включите):

```powershell
powershell -ExecutionPolicy Bypass -File .\schedule.ps1
```

Если пишет «Отказано в доступе» — запустите PowerShell от имени администратора и повторите.

## Как проверить, что работает

- Откройте папку `%USERPROFILE%\Oyuur-backups`: там появляется по файлу в день.
- В `backup.log` — по строчке на каждый запуск. «ВНИМАНИЕ: последняя копия на сервере — N дн. назад» значит, что сервер перестал делать копии: сообщите диспетчеру.
- На странице `/owner` вверху написано «Последняя копия: вчера в 4:00, 2,3 МБ». Там же кнопка «Скачать копию» — тот же зашифрованный файл, если нужно скачать вручную (например, на другом компьютере).
- Проверить любую скачанную копию, ничего не создавая:

```powershell
powershell -ExecutionPolicy Bypass -File .\restore.ps1 -CheckOnly
```

## Как восстановить

1. Превратить последнюю копию в обычную базу:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\restore.ps1
   ```

   Рядом с копией появится `oyuur-ГГГГ-ММ-ДД.db`. Другая копия: `-File путь\oyuur-2026-10-25.oyuurbak`, другое место: `-Out путь\oyuur.db`.
2. Проверить её на своём dev-сервере (в PowerShell, из папки `server`): `$env:DB_PATH='путь\oyuur-….db'; $env:PORT=8790; node src/main.js` — и открыть http://localhost:8790. Лучше на копии этого файла: сервер её дописывает.
3. Вернуть на сервер — только вместе с архитектором: остановить сервер, сделать копию нынешней базы, положить файл как `/data/oyuur.db`, запустить. Сам сервер в момент запуска ещё раз сохранит то, что было (`/data/backups/start-*.db`).

## Если поменяли ключ владельца

Старые копии открываются **старым** ключом — сохраните его где-нибудь надёжно (например, в менеджере паролей), пока копии со старым ключом не уйдут (14 дней). Новый ключ — снова `setup.ps1`.

## Убрать

```powershell
Unregister-ScheduledTask -TaskName 'Oyuur backup'
```

Ключ — файл `%LOCALAPPDATA%\Oyuur\owner-key.dpapi`, его можно удалить.

## Для разработчика: формат файла `.oyuurbak`

Описан в начале `server/src/backup.js`: заголовок `OYUURBK1` + соль (16) + iv (12) + sha256 исходной базы (32), затем
AES-256-GCM(gzip(база)) и 16 байт метки GCM. Ключ = scrypt(OWNER_TOKEN, соль, 32, N=2^14, r=8, p=1); заголовок — AAD.
Новые соль и iv на каждое скачивание. Открывает `restore.mjs` (тот же код, что в тестах сервера).

Проверка без настоящих папок: переменные `OYUUR_BACKUP_FOLDER` (куда копии) и `OYUUR_BACKUP_CONFIG` (где ключ).
